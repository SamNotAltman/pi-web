# Add passkeys as the primary login credential

Pi Web logs in with WebAuthn passkeys; the configured `PI_WEB_PASSWORD` becomes the enrollment and recovery secret instead of the day-to-day credential. The login page leads with "Sign in with passkey" and keeps the password form as a fallback, because browsers only expose WebAuthn in a secure context and therefore cannot offer passkeys over a plain-HTTP LAN address. `PI_WEB_PASSWORD` stays the HMAC key for web session tokens and for the short-lived, signed challenge cookie, so session tokens and in-flight ceremonies are invalidated when the password rotates — registered passkeys are not, because assertions are verified against the stored COSE public key rather than the password. Passkeys are relying-party scoped to the request hostname and stored as public values in `~/.pi/agent/pi-web-passkeys.json`.
